# 승인 시안 재현 — 고정 작업 지시

## 임무
너는 이번 작업에서 새 디자인을 제안하는 사람이 아니라, 사용자가 승인한 화면을 실제 Focus Feed에 재현하는 구현자다. 사용자는 반복된 시안 불일치를 지적했다. 기존 구현이 편하다는 이유로 구조·비율·정보 순서·문구·시각 상태를 재해석하지 않는다. 기능이 동작하는 것과 시안이 재현된 것을 각각 검증한다.

## 시각 정본
첫 대상은 ‘자료와 정리’ 한 화면이다. 이 화면을 맞추기 전 영상/문서 모드를 동시에 손대지 않는다.
- 자료와 정리: `docs/screenshots/workspace-approved-reference.png`
- 영상 집중: `docs/screenshots/workspace-watch-reference.png`
- 문서 집중: `docs/screenshots/workspace-write-reference.png`
아래 절차는 구현 당시의 기준 기록이다. 현재 출시 범위와 검증 한계는 `docs/WORKSPACE_RELEASE.md`를 따른다.

최근 임의 수정 CSS나 짧은 fixture 캡처는 시각 정본이 아니다. 원본의 예시 모델명과 재생 내용은 실제 가용성의 근거가 아니다.

## 먼저 만들 증거
1. 원본을 열고 1536×1024 기준으로 주요 경계, 시작 좌표, 폭, 간격, 글자 크기, 입력창/버튼 높이를 측정한다. 추정값과 확인값을 구분한다.
2. 실제 앱 컴포넌트를 쓰는 결정적인 시각 검증 상태를 만든다. 원본과 같은 제목·본문·문단 수·줄 길이·선택 문단·사용자 요청·AI 응답·제안 펼침 상태를 사용한다. 빈 채팅이나 두 줄 본문으로 대체하지 않는다.
3. 검증 데이터는 테스트 안에서만 공급한다. 실제 사용자 문서·작업·대화·모델 목록을 예시 데이터로 덮지 않는다. 검증 화면임을 명확히 표시한다.
4. 원본, 실제 앱 캡처, 차이를 확인할 수 있는 비교 화면을 한곳에서 볼 수 있게 만든다. 같은 해상도와 상태를 확인한 다음 시각 검토한다.

## 변경 순서
A. 자료와 정리의 큰 경계와 여백을 맞춘다. 원본의 대략적인 417/656/463px 열 폭과 60px 헤더를 출발값으로 삼고 직접 대조한다.
B. 문서 경로·저장 상태·도구 모음·제목·본문·섹션·오른쪽 목차를 순서대로 맞춘다. 제목 약 36px, 본문 약 17~18px, 문단 간격과 실제 줄바꿈을 함께 비교한다.
C. 제공자 표시·모델 선택·선택 문단·요청·응답·수정안·입력창을 원본의 위치와 정보 순서로 맞춘다. 입력창 약 76px와 리턴 키 약 48px를 직접 확인한다.
D. 같은 콘텐츠로 검증한 자료 화면을 기준으로 영상/문서 집중을 구현한다.
E. 360/432/768/1280/1440px 반응형과 키보드·IME·reduced-motion을 확인한다.

수치는 이미지 판독의 출발값이다. 실제 비교 없이 숫자를 맞췄다는 이유만으로 통과시키지 않는다. 사용자 폭 조절은 유지하되 기본 배치와 초기 저장 폭을 구분해서 검증한다.

## 구현 제약
- CSS 덮어쓰기를 계속 아래에 붙이지 않는다. 관련 기존 규칙을 정리하고 각 모드의 배치 책임을 명확히 한다. 다른 작업의 변경은 보존한다.
- 별도의 보기 좋은 정적 데모를 실제 제품 구현으로 보고하지 않는다. 테스트 상태도 같은 제품 컴포넌트를 렌더해야 한다.
- 기존 저장·CAS·승인·세션·모델 연결은 보존한다. 변경이 필요한 경우 필요한 최소 계약을 명시한다.
- 문단 수정 UI는 전체 문서 교체를 문단 교체처럼 꾸미지 않는다. 대상 범위·원문·revision을 검증하는 실제 동작까지 구현해야 완료다.
- 실제 서비스 미연결 때문에 영상/댓글/모델 응답이 없으면 그 사실을 별도로 기록한다. 연결 제한을 이유로 주변 디자인을 바꾸지 않는다.
- 작동하지 않는 버튼과 존재하지 않는 기능을 완성된 제품 UI로 가장하지 않는다.
- 새로운 디자인 취향, 장식, 카드, 색, 메뉴, 설명문을 임의로 추가하지 않는다.

## 두 개의 독립 통과 기준
기능: 저장/승인, 후보 비교·반영·되돌리기, 문단 편집 대상 검증, 상태 보존, 폭 조절, 키보드·IME, 타입/린트/관련 테스트.
시각: 동일 콘텐츠·동일 상태·동일 viewport의 원본/구현 비교, 큰 경계부터 세부 글자와 아이콘까지 차이 목록, 좁은 화면 검증.

큰 경계는 원본 대비 ±4px, 간격/정렬은 ±2~4px를 초기 검토 목표로 삼는다. 글꼴 렌더링 차이는 수치와 육안 검토를 함께 기록한다. 전체 이미지 유사도 수치 하나로 합격시키지 않는다.
비교에서 제외할 수 있는 영역은 영상 픽셀, 사실에 따라 다른 시간·상태 등으로 제한하며 사전에 이름과 이유를 적는다. 레이아웃·글자·AI 패널을 제외 영역으로 숨기지 않는다.

## 보고 규칙
- 원본과 같은 상태의 비교 증거가 없으면 ‘시안대로 구현’, ‘완성’, ‘100%’, ‘거의 동일’이라고 말하지 않는다.
- 테스트 통과는 기능 검증 결과로만 말한다.
- 시각 차이가 남으면 위치와 차이를 구체적으로 기록하고 직접 수정한다. 이미 승인된 시안에 대해 반복해서 사용자에게 방향을 묻지 않는다.
- 해결되지 않은 실제 연결 제약과 아직 구현하지 않은 작업을 구분한다.
- 완료 보고에는 원본/구현 비교, 동작 증거, 남은 차이가 있어야 한다. 미완료를 완료로 포장하지 않는다.

## 현재 출발 상태
기존 화면은 기능과 일부 배치만 구현된 상태이며 시각 재현 불합격이다. 다음 행동은 추가 CSS 수정이 아니라 ‘자료와 정리’의 같은 콘텐츠·같은 대화 상태를 가진 비교 기준을 만드는 것이다.


## Astra 실행 지시와 하네스 적용
공식 근거: https://developers.openai.com/api/docs/guides/latest-model (2026-09-13 확인). 자율 진행 범위, 스킬 충돌 점검, 위임 조건, 필요한 수준의 검증을 명시하라는 가이드를 이 작업에 적용한다. 모델 설정을 변경하거나 별도 유료 세션을 실행했다는 뜻은 아니다.

- 이미 승인된 시각 결정은 재질문하지 않는다. 이미지로 해소되지 않고 결과를 크게 바꾸는 선택만 짧게 인터뷰한다.
- 이 작업의 원본 재현 지시가 frontend-design의 새 미감 탐색 제안보다 우선한다. 더 예쁘게 보인다는 이유로 원본을 바꾸지 않는다.
- 지휘자는 원본과 실제 화면의 대조·최종 판정을 맡는다. 독립 검토자는 사용자 발화에서 누락 요구만 추출하며 계획을 먼저 읽지 않는다. 구현 writer는 하나로 유지한다.
- 긴 전체 대화 대신 확정 요구 목록, 승인 이미지, 해당 컴포넌트, 실패한 증거만 현재 구현 맥락에 둔다.
- 한 번에 자료와 정리 한 화면의 비교를 닫는다. 같은 오류 없이 통과한 검사 전체를 사소한 문구 수정마다 반복하지 않는다. 새 동작·회귀 위험·실패는 해당 검사로 확인한다.
- 스킬 이름이나 프롬프트 자체를 품질의 증거로 제시하지 않는다. 실제 캡처와 실행 결과를 제시한다.

## 요구사항 누락 대조와 결정
블라인드 검토자가 사용자 발화 발췌만 보고 14개 항목을 추출했다. 이 결과는 발화 전체를 도구로 추출하는 plan-audit 정식 절차의 통과를 뜻하지 않는다. 원본 시안과 기존 합의를 지휘자가 추가 대조했다.

| 요구 | 이번 결정 / 실제 상태 | 완료 증거 |
|---|---|---|
| 순백색, 중성색, 노션처럼 단순한 미감 | 승인 이미지 우선, 밤색/아이보리 제외 | 같은 상태 캡처 필요 |
| 3개 시안의 충실한 재현 | 자료와 정리부터 고정하여 비교 | 첫 기준 1536×1024 |
| 자료/문서/AI 구성 | 실제 앱 컴포넌트 재사용 | 기존 배치 E2E + 시각 비교 |
| 오른쪽 아래 AI 열기·접기 | 접었을 때 같은 채팅을 다시 여는 진입점 추가 | 문단 E2E에서 대화 보존 확인 |
| 패널 너비 조절 | 드래그/키보드, 초기 폭은 417/463px | 폭별 검증 |
| 영상/문서 집중 | 메모/질문/본문 수정까지 구현하고 시안별 대조 | 최종 캡처와 E2E |
| 영상/자막/소스 가이드/댓글 | 자막은 확보된 발췌라고 표시. 댓글 미수집 상태와 원본 열기 제공 | 실제 수집 자동화 미구현 |
| Markdown 편집·요약·수정 | 기존 손편집/서식/저장 + AI 연계 | 단위/E2E |
| 핵심 요약·내 생각·다음에 해볼 것, 목차 | 시안 검증 fixture에 같은 내용, 실제 문서는 강제 변환하지 않음 | 같은 상태 캡처 |
| 선택 문단 수정 | 정확한 원문/위치/revision으로 후보 생성, 명시 반영 및 되돌리기 | 단위/E2E |
| 본문 안 제안 및 요청 | 우측 후보와 동일 상태·CAS를 공유하는 본문 요청/적용/되돌리기 구현 | 인라인 E2E |
| AI 브랜드·도구·모델 | 도구/모델 실제 목록 유지, 브랜드 아이콘 원본 라이브러리 사용 | 연결 실패 상태 별도 |
| 애니메이션/리턴 키/구분 강약 | 입력키 눌림, 선택 강조, reduced-motion. 시안 밖 장식 제외 | 브라우저 확인 |
| 프로필/공유 | 개인 프로필 제외. 공유는 목적 미정으로 보류, 브레인 승인과 혼동하지 않음 | 헤더 검토 |
| 사용 효율·과설계 방지 | 두 번째 채팅 엔진/새 스케줄러/새 문서 저장소 미추가 | 코드 검토 |
| 저장·승인·오류·빈 상태 | 기존 계약 보존, 미수집/미연결 상태를 성공처럼 표시하지 않음 | 관련 회귀 검사 |

추가 디자인 인터뷰를 막는 미결정은 없다. 댓글 수집 API/영상 시간 연동/공유 목적은 외부 연결 또는 후속 제품 결정이며, 승인된 화면의 재현을 중단할 이유가 아니다. 구현되지 않은 요구는 이 표에서 삭제하지 않는다.

## 구현 결과
세 집중 화면, 문단 수정과 되돌리기, AI 패널 재진입, 영상 시점 연결을 구현했다. 최신 통합 범위·검증 결과·남은 외부 연결 제약은 [작업실 릴리스 기록](../../WORKSPACE_RELEASE.md)을 따른다. 댓글·NotebookLM 자동 수집과 공유 목적은 후속 범위로 남긴다.
