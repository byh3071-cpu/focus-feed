# 자료를 보며 생각을 문서로 남기는 작업실

## 목적과 범위
사용자는 영상에서 필요한 근거를 찾고 자기 생각을 문서에 남기며, 필요한 순간 AI로 수정한다. 새 기능 수보다 창 이동·재탐색·잘못된 덮어쓰기를 줄이는 데 집중한다. 현재 사용자 승인 이미지의 순백색, 중성 회색, 선택 상태의 옅은 파랑을 유지한다. 프로필·공유·반복되는 역할 제목·과한 카드와 구분선은 제외한다.

이번 문서는 승인된 작업실 프런트엔드 설계와 실제 구현·검증 기록이다. 하단 기록은 시간순 이력이며 최신 판정은 `docs/screenshots/design-qa.md`를 따른다. 기존 다른 작업의 변경은 보존했다.

## 확인한 기반과 연결 지점
- src/app/knowledge/KnowledgeStudio.tsx: source/rail 폭 저장과 드래그, Markdown draft/revision, PATCH 및 승인 흐름. 재사용한다.
- src/app/knowledge/KnowledgeStudioAgent.tsx: 도구/모델 선택, health 목록, 도구+모델 세션, WebSocket/SSE, 편집 가능한 초안에 대한 자동 PATCH. UI를 다듬되 연결 계층은 재사용한다.
- src/lib/knowledge-studio.ts, knowledge-studio-agent.ts, knowledge-agent-protocol.ts: 기존 계약과 테스트를 유지한다.
- 현재 플레이어는 일반 YouTube iframe. 같은 플레이어 인스턴스 유지와 실제 시간/seek 연동 검증이 추가로 필요하다.
- 현재 PRD의 모델 선택 위치(입력창)와 자동 PATCH 정책은 새 설계(상단 선택, 비교 후 반영)와 다르다. 실제 구현 increment에서 PRD도 함께 갱신한다.
- 현재 자막 전체와 댓글 전체가 제공된다고 가정하지 않는다. 실제 payload의 소스 가이드/짧은 근거만 우선 노출한다. NotebookLM 생성 결과와 영상 설명 기반 가이드를 명확히 구분한다.

## 화면과 상태
자료와 정리: 자료 / 문서 / 선택적으로 AI. 목차는 문서 여백에 둔다. 공간이 부족하면 목차를 접고, 4번째 열을 만들지 않는다.
영상 집중: 영상이 주요 공간, 자막 또는 메모가 옆에 위치. 문서는 숨겨도 초안·선택·스크롤을 보존한다.
문서 집중: 읽기 폭을 제한한 문서 + 작은 목차. 영상 미니플레이어는 사용자가 켠 경우에만 유지한다.

한 job에 layoutMode, sourceWidth, aiWidth, aiOpen, sourceTab, scrollPositions, selection, draft/revision, player state를 구분한다. UI 배치 상태와 서버 초안 상태를 분리한다. 배치 전환은 API 저장·모델 호출을 발생시키지 않는다. 플레이어를 모드마다 새로 mount하지 않는다. 같은 job 전환에서는 유지, job 변경에서는 해당 작업 상태로 명시적으로 전환한다.

초기 폭은 현재 코드 값을 재사용하고 문서 최소 가독폭을 보장한다. 폭 조절은 pointer capture, pointercancel 정리, 키보드 좌우 조절, separator 접근성 이름, 기본 배치 복원을 포함한다. localStorage 실패 시 메모리 상태로 동작한다. 좁은 화면에서는 억지로 3열을 유지하지 않는다.

## 자료와 문서의 연결
- 목차는 실제 Markdown headings에서 생성한다. 핵심 요약/내 생각/다음에 해볼 것은 편집 가능한 기본 틀이며 강제 schema가 아니다.
- 출처 클릭은 가능한 경우 같은 플레이어를 seek한다. 연동 불가이면 원본에서 열기를 명시한다.
- 자막 따라가기는 사용자가 과거 자막을 스크롤하면 일시 정지하고 현재 재생 위치로 버튼을 제공한다.
- 현재 시점 메모는 지원되는 실제 시간만 기록한다. 플레이어 미연결이면 가짜 시간을 넣지 않는다.
- source guide, transcript excerpt, comment 등 실제 출처 종류와 확보 범위를 표시한다. 미수집 댓글 탭은 빈 데이터와 수집 동작을 구분한다.

## AI 및 문단 수정
상단: 작은 실제 제공자 표시 / 실행 도구 / 실제 사용 가능한 모델. 대화 제목과 분리한다. 오프라인 fallback 모델 목록을 연결 검증된 목록처럼 표시하지 않는다. 실행 중 변경은 잠그거나 다음 요청 적용으로 명시한다. 모델/도구 전환 시 세션이 유지된다고 보장하지 않고 현재 코드 세션 키를 존중한다.

일반 질문은 대화만 추가한다. 문서 수정은 후보를 만들고 사용자 적용 전 PATCH하지 않는다. 짧은 문단 수정은 문단 바로 아래, 긴 대화는 우측에서 진행하며 하나의 후보/실행 상태를 공유한다. 중복 채팅 엔진을 만들지 않는다.

후보 최소 상태: baseRevision, originalText, replacementText, targetRange, status. 후보 생성 이후 사용자가 문서를 고쳤다면 범위를 재확인한다. originalText가 안 맞거나 동일 문장이 중복되어 대상을 확정할 수 없으면 적용 중단 및 다시 비교. 외부 세션의 revision 충돌은 기존 expectedRevision/CAS에 위임한다.

반영 전: 변경 이유 한 줄 + 실제 전후 비교 + 이 문단 바꾸기/취소.
반영 후: 반영됨 + 되돌리기. 되돌리기도 새 편집이며 그 후의 사용자 수정을 덮지 않도록 현재 revision/본문을 확인한다.
문단 수정과 전체 문서 교체는 별도 행동이다. 기존 Markdown 코드펜스 응답을 임의의 문단 patch로 해석하지 않는다. 첫 구현은 전체 문서 후보 비교를 정확히 지원하고, 문단 범위가 검증된 경우에만 문단 교체를 제공한다.

## 저장과 승인
편집 저장과 Brain 승인은 별개다. 현재 권한/상태 계약을 보존한다. 초안 변경이 저장되지 않았거나 충돌 상태면 성공 표시를 하지 않는다. 완료/승인본은 기존 amendments 흐름으로 연결한다. 승인은 서버 접수와 실제 적재 완료를 구분한다. 이 설계로 자동 승인을 추가하지 않는다.

## 미감과 모션
배경 #FFFFFF, 본문 #242424, 보조 #646464, 경계 #E9E9E9, 선택 #EAF1FF. 대비는 실제 렌더에서 검증한다. 본문 16px/1.7, 보조 14px, 제목 28~32px를 시작값으로 쓴다.
단일 세로 경계로 영역 구분. AI 대화 내부 구분선은 제거하고 간격/정렬로 위계를 만든다. 입력창만 부드러운 곡선과 옅은 깊이를 가진다.
전송 키는 100ms 전후 눌림, 입력창 펼침 180~240ms, 배치 전환 180~240ms를 출발점으로 비교한다. 수치는 제품 실측으로 조정하는 제안이다. reduced-motion은 즉시 상태 전환. 빈번한 입력을 지연시키지 않고 연속 열기/닫기에 중단 가능한 전환을 쓴다. 한글 조합 Enter는 전송하지 않는다. Enter/Shift+Enter 정책과 접근성 이름을 일치시킨다.

## 구현 순서와 완료 기준
1. 작업 공간: 기존 폭 hook에 세 배치/AI 접기/목차를 연결. 문서 DOM/초안/플레이어 인스턴스 유지. 모드 전환과 복원, 키보드 폭 조절 검증.
2. 편집 보호: 자동 PATCH를 후보 비교/적용으로 전환. 정상 적용, 취소, 후보 이후 사용자 편집, 409, 되돌리기, 질문만 하는 경우를 검증.
3. 자료 연결: 플레이어 시간/seek, 실제 근거 클릭, 시점 메모, 따라가기/복귀. 외부 iframe 실패를 정상 재생처럼 보고하지 않는다.
4. 시각 정밀화: 선택된 이미지와 동일 viewport에서 대조. 360/432/768/1280/1440에서 넘침, 포커스, motion 감소, 긴 제목과 긴 답변 확인.

처음부터 추가하지 않을 것: 임의 분할/무한 캔버스, 모든 도구 통합, 자동 지식 승격, 새로운 RAG, 공유/프로필, 확정되지 않은 댓글 수집 경로.

## 시안 대조 후 재구현 — 2026-09-13
이전 구현을 시안 재현 완료로 보지 않는다. 승인 이미지와 비교하여 다음을 수정했다.

- 헤더 한 줄(60px)과 중앙 보기 전환. 작업 승인과 보류는 실제 기능으로 유지한다.
- 문서 경로/저장 상태, 가벼운 서식 도구, 제목·본문·섹션 간격. 목차는 넓은 화면에서 본문 오른쪽으로 옮겼다.
- 도구·모델을 AI 상단 한 줄로 결합. 사용자 요청만 회색 말풍선, 입력창은 72px로 낮췄다.
- 문서 모드 작은 영상은 오른쪽 아래이며 닫기 버튼이 동작한다.
- 영상 모드의 영상·근거·영상 아래 제목을 명시적인 grid 위치로 분리했다.
- 서식 도구는 선택 영역의 제목/굵게/기울임/링크 Markdown을 편집하며, 보기에서 지원 서식을 렌더한다. 새 편집 엔진을 설치하지 않았다.
- 실제 캡처: docs/screenshots/workspace-study-revised.png, workspace-watch-revised.png, workspace-write-revised.png. 검증용 데이터이며 영상 영역은 재생을 가장하지 않는 테스트 자리다.

남은 시안 차이: 실제 제공자 로고 자산, 문단 선택·본문 안 제안/적용, 자막 따라가기·시점 메모·챕터, 같은 내용과 상태의 최종 시각 비교. 전체 시안 완료로 승격하지 않는다.

## 요구 대조와 문단 수정 구현 — 후속 기록
위 남은 항목 중 제공자 로고, 선택 문단의 범위/revision 검증과 우측 제안·반영·되돌리기, 비교용 콘텐츠 fixture를 구현했다. AI를 닫아도 오른쪽 아래에서 같은 대화를 다시 연다. 일반 질문의 Markdown 답변을 편집 후보처럼 숨기지 않는다. 원문 선택이 오래되면 재선택을 안내한다.

실행 기준은 `2026-09-13-workspace-visual-implementation-brief.md`에 고정했다. `docs/screenshots/workspace-comparison.html`은 원본/구현의 비교 산출물이며 실제 앱을 대체하는 데모가 아니다. 목차가 본문에 가려 클릭되지 않던 문제를 실제 클릭 검증으로 찾아 수정했다.

아직 남는 범위: 본문 안 요청/제안, 실제 댓글·자막 시간 연동, 시점 메모, 집중 모드별 최종 시각 대조. 공유는 전달 목적이 정해질 때 결정한다. 현재 상태는 계속 `partially-implemented`다. 상세 실행 결과와 시각 차이는 `docs/screenshots/design-qa.md`를 따른다.

## 전체 디자인 마무리 — 최신 기록

Astra가 통합 writer를 맡고 Sol(시각 대조), Terra(문단 수정 계약), Luna(키보드/모바일/오류 경계)를 사용했다. 승인된 세 모드를 실제 앱에서 구현했다. 본문 인라인과 우측 제안은 같은 Agent의 상태와 CAS를 사용하고 동기 operation lock으로 중복 전송·반영을 차단한다. 중복 문단은 원문 범위로 구분한다.

영상 집중의 메모는 같은 Markdown에 저장하고, YouTube IFrame API로 준비된 플레이어만 제어한다. 시간 탐색 스트립은 확보된 발췌이며 존재하지 않는 챕터를 생성하지 않는다. 낮은 창 높이에서는 메모와 질문창을 순서대로 배치해 겹침을 방지한다.

시각 세부, 반응형, 실제 조작 결과는 검증 리포트에 남긴다. 실제 댓글 수집과 NotebookLM 처리 자동화는 디자인 완료와 별개인 외부 서비스 작업이다. 개인 프로필·목적 없는 공유는 추가하지 않았다.
